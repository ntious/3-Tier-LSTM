# Contributing

Contributions that improve reproducibility, documentation, evaluation, testing, accessibility, or responsible research use are welcome.

## Development principles

- Open an issue before a substantial change.
- Keep data preprocessing, training, evaluation, and explanation steps clearly separated.
- Document dependency changes, random seeds, data splits, and expected outputs.
- Add or update tests for changed behavior where practical.
- Do not commit credentials, protected health information, or non-redistributable datasets.
- Distinguish measured results from proposed or expected results.

## Pull requests

Use a focused branch and explain the problem, approach, validation performed, and any limitations. A change affecting reported results should include enough information to reproduce the new result and should not overwrite prior evidence without explanation.
